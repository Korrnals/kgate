# Администрирование · Сегменты и политики ndm

> 🔴 **Главные грабли интеграции.** Политика ndm, назначенная сегменту,
> перекрывает тумблер для всех его устройств. Это конфигурация ndm, а не kgate.

## 🧭 Модель

`ip hotspot` в ndm хранит по-сегментные политики:

| Сегмент | Конфигурация | Поведение устройств |
|---|---|---|
| Home (Bridge0, 192.168.1.x) | `policy Home permit` | следуют дефолтной политике → тумблер управляет |
| Bridge1 (192.168.2.x) | `policy Bridge1 permit` | аналогично |
| SMART (Bridge2, 192.168.3.x) | `policy Bridge2 permit` (было `DIRECT-NOVPN`!) | следуют тумблеру |

Индивидуальные привязки устройств (`host <mac> policy DIRECT-NOVPN`) имеют
**приоритет над сегментными** — так реализуются IoT-исключения: пылесос,
кондиционеры и т.п. остаются напрямую даже при ON.

## 🔍 Проверка

```bash
ssh router 'ndmc -c "show running-config"' | sed -n '/^ip hotspot/,/^!/p'
ndmc -c "show ip hotspot"          # живые клиенты: mac, ip, сегмент
```

Симптом «тумблер ON, а сайты с домашним IP / not available in your region» —
почти всегда устройство в сегменте с `DIRECT-NOVPN` либо индивидуальная привязка.

## ✏️ Изменение

```bash
# сегмент → дефолтная политика (тумблер начнёт управлять)
ndmc -c "ip hotspot policy Bridge2 permit"

# сегмент → постоянный прямой доступ
ndmc -c "ip hotspot policy Bridge2 DIRECT-NOVPN"
```

В веб-интерфейсе: **Приоритеты подключений → Применение политик**.

> [!WARNING]
> Галки в «Политике по умолчанию» веб-интерфейса не редактируются — это
> приоритетная модель ndm (все подключения участвуют по `ip global`
> приоритетам: Proxy0=800, ISP=700). Управление — тумблер, приоритеты
> и кастомные политики, не галки.

## 🔗 Взаимодействие со стеком kgate

- Трафик сегмента с `permit` → политика → tun2socks → relay → sing-box
  (RU-сплит внутри движка).
- Трафик сегмента с `DIRECT-NOVPN` → ISP напрямую, туннель не участвует.
- Индивидуальные IoT-привязки сохраняются при любом положении тумблера.

## 🩺 Диагностика «прокси включён, а трафик прямой»

1. `kgate status` — relay/sing-box running, Proxy0 up.
2. Проверьте сегмент устройства (`show ip hotspot`) и его политику.
3. Выходной IP фактически: `curl -sS https://1.1.1.1/cdn-cgi/trace | grep ip=`
   (hardware-offload Keenetic делает tcpdump слепым — верьте тестам выходного IP).
