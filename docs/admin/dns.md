# Декларативные DNS-записи (`dns.hosts`)

Секция `dns.hosts` в `kgate.yaml` — статические host-записи роутера
(fqdn → IPv4), применяемые `kgate apply` идемпотентно. Структурный близнец
слоя [policies](segments-and-policies.md): дельта считается в Go по живому
running-config, исполняются только недостающие вербы, затем один save —
повторный apply на сошедшемся состоянии не трогает flash.

## Как это работает

- **BIND**: `ip host <fqdn> <ip>` — запись появляется в running-config
  top-level строкой `ip host <fqdn> <ip>`.
- **UNBIND**: `no ip host <fqdn>` — снимает запись (используется только
  в `kgate destroy`, до снятия policies-привязок).
- fqdn есть, ip отличается от декларации → re-bind той же формой
  (ndm перезапишет запись).

```yaml
dns:
  hosts:
    nas.abyss.lab: 192.168.1.10
    vpn.abyss.lab: 203.0.113.10
```

## Валидация

- fqdn — только `[a-z0-9.-]`, минимум одна точка, метки без ведущего/хвостового
  дефиса; кавычки, shell-метасимволы и underscore отсечены charset'ом
  (ndm-безопасность — вербы интерполируются в `ndmc -c`);
- ip — строгая IPv4-форма (`net.ParseIP` + требование v4).

## Стадия apply

`DNSHosts` выполняется сразу после `Policies`:

1. чтение живого `show running-config` (PTY, до 3 попыток с бэкоффом 2s/4s —
   полевой кейс: ndm после тяжёлых стадий кратко отдаёт пустой вывод);
2. парсинг top-level строк `ip host <fqdn> <ip>` после `StripANSI`
   (PTY-вывод ndmc несёт `\x1b[K` и `\r`);
3. исполнение только расходящихся bind-вербов (детерминированный порядок —
   отсортированные fqdn), вербальная поверхность отказа ndmc проверяется
   на каждом вербе;
4. один `system configuration save`, если было что писать.

Пустая/отсутствующая секция = стадия честно рапортует «не декларировано»
и ничего не делает (fail-safe: штатный dhcp-dns роутера сохраняется).

## Destroy

`kgate destroy` снимает ровно декларированные записи (`no ip host <fqdn>`)
до снятия policies-привязок и удаления политик; пункт отражён в плане
destroy.
