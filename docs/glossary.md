# Глоссарий

> 📖 Канонические термины документации kgate. Используйте эти формы во всех
> доках и коммуникациях; EN-термины (relay, payload, route-pins) не переводятся.

## 🧩 Ядро kgate

| Термин | Определение |
|---|---|
| **kgate** | утилита управления VPN-стеком: один Go-бинарь в трёх ролях — демон, клиент, деплойер |
| **демон-супервизор** | `kgate serve` на роутере: следит за процессами, DNS-правилами, туннелем, mTLS API |
| **деплойер** | `kgate deploy` (алиас `apply`): установка и обновление стека по ssh идемпотентными стадиями |
| **движок** | sing-box — ядро маршрутизации: RU-сплит, выходной туннель, дашборд `:9090` |
| **socks-relay** | локальный SOCKS-мост `:1090`: принимает любые verбы ndm-клиента, транслирует в CONNECT к движку |
| **тумблер** | переключатель VPN для дома: Proxy0 up/down — CLI `kgate toggle`, веб-интерфейс, API `/toggle` |

## 🧭 Режимы и маршрутизация

| Термин | Определение |
|---|---|
| **RU-сплит** | режим `Rule`: RU-адресаты — напрямую, зарубежные и RU-медиа — через туннель |
| **RU-exit** | режим `Global`: весь трафик дома идёт через выходной узел туннеля (анонимизация) |
| **clash_mode** | внутренний переключатель режимов движка `Rule`/`Global`; им управляет `/api/v1/ruexit` |
| **hy2** | протокол выходного туннеля (Hysteria2, HTTP/3) |
| **route-pins** | статические маршруты `/32 → ISP`: выводят hy2-сервер и DNS из туннельной политики (защита от петель) |

## 🌐 ndm и роутер

| Термин | Определение |
|---|---|
| **ndm** | ОС роутера Netcraze / Keenetic и её CLI (`ndmc`) |
| **Entware** | пакетное окружение в `/opt` — среда жизни демона и движка |
| **Proxy0** | туннельный интерфейс ndm — физический носитель тумблера |
| **tun2socks** (`t2s0`) | компонент ndm: заворачивает помеченный трафик в SOCKS на наш relay |
| **сегмент** | группа устройств ndm (Bridge0/1/2) со своей политикой |
| **политика (policy-v2)** | ровно две: `VPN` (через туннель) и `NO-VPN` (напрямую); без привязки = честный дефолт — напрямую (Proxy0 `ip global 1200`) |
| **бут-гонка** | состояние гонки ndm ↔ Entware при старте; демон исключает её ожиданием `:1080` |

## 🛡 Безопасность

| Термин | Определение |
|---|---|
| **mTLS** | взаимная TLS-аутентификация: клиент и сервер предъявляют сертификаты одного CA |
| **CA** | корневой сертификат деплоя (ECDSA P-256, 10 лет) — источник доверия всего набора |
| **клиентский набор** | `ca.crt` + `client.crt` + `client.key` в `~/.kgate/` на ноутбуке |
| **web_root** | каталог серверных сертификатов на роутере (`/opt/etc/kgate/`) |

## 📦 Деплой

| Термин | Определение |
|---|---|
| **payload** | самодостаточный `tar.gz`: бинари kgate и sing-box, init-скрипт, конфиги |
| **стадия deploy** | шаг деплоя: `preflight` / `files` / `config` / `migrate` / `ndm` / `services` |
| **opkg-фид** | HTTP(S)-репозиторий пакетов opkg (gh-pages этого репо): `opkg install kgate` |
| **шаблон `.example`** | конфиг-шаблон в `.ipk`; `postinst` создаёт из него живой конфиг только при первом запуске — переустановка пакета не затирает правки |
| **плейсхолдеры** | маркерные значения в шаблонах (`203.0.113.10`, `hy2.example.com`, `HY2_PASSWORD`); демон детектит их при старте и намеренно не поднимает туннель |
| **rule-set** (`.srs`) | бинарный файл правил классификации sing-box |
| **FD-лимит** | `RLIMIT_NOFILE`, наследуемый sing-box от демона |
