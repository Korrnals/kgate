# API · Аутентификация и общие правила

## Транспорт и аутентификация

- базовый URL: `https://<роутер>:9443`
- транспорт: **TLS 1.2+** с **взаимной** аутентификацией (mTLS):
  - сервер предъявляет сертификат, выпущенный CA деплоя (SAN: IP роутера, `kgate`);
  - клиент обязан предъявить клиентский сертификат из того же CA —
    соединение без него отклоняется на этапе handshake.
- пароли/токены не используются: единственный фактор — обладание `client.key`.

## Набор сертификатов

| Файл | Роль | Расположение |
|---|---|---|
| `ca.crt` | корневой CA (доверие обеих сторон) | ноутбук + роутер |
| `server.crt` / `server.key` | сертификат API-сервера | роутер: `/opt/etc/kgate/` |
| `client.crt` / `client.key` | сертификат клиента | ноутбук: `~/.kgate/` |

Генерация — автоматическая при `kgate apply` (ECDSA P-256, срок 10 лет).
Перевыдача CA требует обновления клиентского набора.

## Конвенции

- база всех путей: `/api/v1`
- `GET` — только чтение; `POST` — действие
- тела — JSON (`Content-Type: application/json`)
- коды: `200` — успех; `400` — некорректное тело; `404` — неизвестный путь;
  `500` — внутренняя ошибка демона
- `/reboot` завершается обрывом соединения — это ожидаемое поведение

## Доступность

API слушает на LAN-интерфейсе роутера (`:9443`). Наружу (интернет) не
экспонируется. Ограничение доступа — файловая/сетевая политика сегмента.
