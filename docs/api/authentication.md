## 🔒 Транспорт и аутентификация

- базовый URL: `https://<роутер>:9443`
- транспорт: **TLS 1.2+** с **взаимной** аутентификацией (mTLS):

  - сервер предъявляет сертификат, выпущенный CA деплоя (SAN: IP роутера, `kgate`);
  - клиент обязан предъявить клиентский сертификат из того же CA — соединение
    без него отклоняется на этапе handshake.

- пароли и токены не используются: единственный фактор — обладание `client.key`.

## 🗂 Набор сертификатов

| Файл | Роль | Расположение |
|---|---|---|
| `ca.crt` | корневой CA — доверие обеих сторон | ноутбук + роутер |
| `server.crt` / `server.key` | сертификат API-сервера | роутер: `/opt/etc/kgate/` |
| `client.crt` / `client.key` | сертификат клиента | ноутбук: `~/.kgate/` |

Генерация автоматическая при `kgate deploy` (ECDSA P-256, срок 10 лет).
Перевыдача CA требует обновления клиентского набора на всех ноутбуках.

> [!IMPORTANT]
> Клиентский ключ (`~/.kgate/client.key`) — это и есть доступ к API: он
> заменяет пароль. Храните его как секрет. Серверные `ca.crt`/`server.crt`/
> `server.key` генерируются при `deploy` локально и загружаются на роутер
> (`server.key` — права `0600`, живёт в `web_root` роутера).

## 📏 Конвенции API

- база всех путей: `/api/v1`
- `GET` — только чтение; `POST` — действие
- тела запросов и ответов — JSON (`Content-Type: application/json`);
  исключения: `/logs` — plain text, тела ошибок — plain text
- коды ответов: `200` — успех; `400` — некорректное тело; `404` — неизвестный
  путь; `500` — внутренняя ошибка демона

Карта всех эндпоинтов с примерами — [Эндпоинты: обзор и навигация](endpoints.md).

## 🧯 Ошибки handshake

Отказ аутентификации происходит **до HTTP** — статуса при этом нет:

```text
curl: (56) OpenSSL SSL_read: OpenSSL/3.x: error:0A00045C:SSL routines::tlsv13 alert certificate required
```

```text
curl: (35) ... TLS alert unknown ca
```

- нет клиентского сертификата → `certificate required`;
- сертификат выпущен другим CA → `unknown ca`;
- не совпал SAN сервера → `hostname mismatch` — проверьте адрес роутера.

> [!TIP]
> Первая диагностика при любой ошибке API: `curl -v ... 2>&1 | grep -i 'alert\|error'` —
> handshake-ошибки видны в TLS-уровне до отправки запроса.

## 🕳 Доступность

API слушает на LAN-интерфейсе роутера (`:9443`). Наружу (интернет) не
экспонируется. Ограничение доступа — файловая и сетевая политика сегмента.
